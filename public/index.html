            LLM
            

              
How LLM judge scores each run

              

                A fixed judge model checks meaning with a second call, instead of comparing text mechanically.
              

            

          

          
    
            
  1. Your prompt generates a candidate output.
    2. 
            
  2. The judge receives that output and the Expected Answer.
    3. 
            
  3. The judge returns a correctness score from 0 to 1.
    4. 
          

          

        


        

          

            REGEX
            

              
How regular expression match scores each run

              

                Checks whether the output follows a pattern, such as an ID, date, or required response format.
              

            

          

          
    
            
  1. Write a regular expression in Expected Answer.
    2. 
            
  2. The checker tests each generated output against that pattern.
    3. 
            
  3. A match scores 1; no match or an invalid pattern scores 0.
    4. 
          

          

            Example: ^ABC-\d{3}$ matches ABC-123. Use ^ and $ when the whole output must match.
          

        


        

          

            JSON
            

              
How Valid JSON scores each run

              

                Checks whether the complete output is correctly formatted JSON that an application can parse.
              

            

          

          
    
            
  1. The checker trims the generated output.
    2. 
            
  2. It attempts to parse the complete output as JSON.
    3. 
            
  3. Valid JSON scores 1; invalid JSON scores 0.
    4. 
          

          

            Expected Answer is not required. Markdown fences or explanatory text outside the JSON make the output invalid.
          

        


        

          

            FIELDS
            

              
How field match scores each run

              

                Checks labeled lines such as Diet: VEGAN, so free-text lines can vary without failing the run.
              

            

          

          
    
            
  1. Write the lines you want checked in Expected Answer, one Label: value per line.
    2. 
            
  2. The checker finds the line with the same label in the output. The label must start the line.
    3. 
            
  3. The score is the share of those lines whose values match. Letter case, extra spaces, a final period, and the order of comma-separated items are ignored.
    4. 
          

          

            Lines you leave out of Expected Answer are not checked. Markdown such as **Diet:** does not count as the label.
          

        


        

          

            CHECK
            

              
How your custom check scores each run

              

                A fixed judge model applies the criteria you wrote in the Custom check panel.
              

            

          

          
    
            
  1. Your prompt generates an output.
    2. 
            
  2. The judge reads your criteria, the case input, the output, and the Expected Answer if there is one.
    3. 
            
  3. It answers PASS (score 1) or FAIL (score 0) with a one-sentence reason.
    4.
